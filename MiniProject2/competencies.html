MP2 claims

What this project demonstrates

Each claim connects the project work to a course competency and a specific part of the code, interface, or analysis.

  1. 01

    C8 - Complete tool

    Public dashboard plus Python pipeline

    I built DocketSignal so a legal-tech or UX researcher can scan public legal-AI concerns, then check the excerpts behind each theme. The public tool lives in index.html, with supporting design, competency, and reflection pages.

  2. 02

    C4 - API data

    Reddit API, local credentials, source context

    I added a live Reddit collection path in src/collect_reddit.py using PRAW. The README and .env.template explain how credentials stay local, and the dashboard keeps subreddit, source type, score, and source link visible.

  3. 03

    C3 - Cleaning

    Messy public text to consistent CSVs

    src/pipeline.py handles sample loading or live collection, cleanup, empty-row checks, deduplication, theme assignment, excerpt selection, and output writing. The cleaned and coded files are saved as an audit trail.

  4. 04

    C5 - Analysis

    Theme counts plus supporting excerpts

    The analysis answers practical questions: which legal-AI themes show up most, which excerpts support them, and what source context sits behind each claim. The main outputs are theme_summary.csv, illustrative_excerpts.csv, and memos.md.

  5. 05

    C6 - Visualization

    Ranked themes and evidence panels

    I used simple ranked views because the labels are long and the goal is comparison. The chart should match the summary table and help the reader check the point quickly.

  6. 06

    C7 - Judgment

    Limits, evidence, and product use

    I scoped the tool as research support. Reddit posts are public discourse signals, not verified facts or legal advice. The useful part is the trace from theme, to excerpt, to source context, to product implication.

C2 - Documentation and cross-discipline framing

The project has to be understandable to someone else

I packaged the project so someone else can understand the input, the output, and the limits. The README, mp2.md, reflection.md, .env.template, notebook, and generated CSVs make the work easier to inspect.

My law and UX research background show up together here. From law, I ask what supports the claim and what risk might be hidden. From UX research, I ask who needs the claim and what decision it helps them make.
